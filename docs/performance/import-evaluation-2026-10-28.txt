Import allocations and dependency evaluation — 2026-10-28

Implementation
--------------
CatalogueStorage keeps JSON, compressed and verification buffers for one write
operation. Each page is serialized once, hashed, and either compressed into the
reusable buffer or compared against its stored, streaming decompression. Reuse
checks compressed digest, exact decompressed input, lengths, end-of-stream,
chunk count, positions and the existing 48-KiB SQL transfer bound. No verification
result survives the write. Corrupted historical objects cannot be certified by
a cached hash. Both old formats and GLCM1 remain unchanged and readable.

Object metadata and chunk count use one database query. For each reused object,
this replaces three separate calls (existence, metadata and count), retaining
the individual bounded BLOB reads. ArmyStore also batches alias migration and
canonical-name updates using the native adapters' prepared statements, in the
same order and transaction as before. Saved entry IDs and source history remain.

RuleDependencies compiles immutable unit/card evidence into local, roster-reader
and unknown facts. It examines inactive branches, recipient conditions,
attachment permissions, association constraints, modifier conditions and repeats.
Actual cross-entry reads add dependency edges. Dirty entries expand through old
and new attachment edges and the reader graph before either convergence phase.
Roster consumers are invalidated by any changed contributor: matching only old
keywords would miss newly granted keywords. This is deliberately conservative;
it does not yet prove that an unrelated changed keyword cannot affect a count.

Add/remove/replace/order edits preserve unrelated results, including exact
copy-label provenance. Muster nomination changes invalidate selected entry IDs
and their dependants. Army name/disposition changes reuse effective states.
Other context changes, unknown dependencies/scopes, unsupported schema versions
and nonconvergence retain full evaluation. Both convergence phases and the
enhancement self-eligibility exclusion remain. No pricing/validation shortcut
was added. Removed dependency IDs are pruned; weak caches retain no history chain.

LibraryRecoveryVersion.Evaluation is army-evaluation-3. When adding condition
kinds, association scopes, direct roster reads or effective context inputs,
update dependency compilation and compare against EvaluateFull. Do not infer
support from an unfamiliar scope string or a previously false predicate.

Verification design
-------------------
The shared IncrementalEvaluationWorkload runs unchanged on host and isolated
Android builds. It covers transitive roster grants, force-wide association limits
that invalidate another group's attachment, local/roster/force constraints and
repeats, additions/removals/replacements/order/copy labels, muster context,
unknown branches and 80 seeded mixed edits including cached undo states.
Every resulting effective state is compared in full with EvaluateFull.

Storage regressions independently damage lengths, digests, missing/extra/shifted
chunks, oversized BLOBs, valid gzip carrying the wrong JSON and trailing decoded
bytes. Reusing those pages must reject and roll back publication. Existing tests
cover complete round trips, legacy formats, stale previews, interrupted writes,
prepared projection rejection, history, provenance and saved armies/context.

The first focused run exposed a test-fixture error: numeric modifiers used the
textual 'add' operation. Both full and incremental evaluators agreed; fixtures
were corrected to use 'increment', and the focused checks then passed. No rule
behavior was changed to accommodate that fixture.

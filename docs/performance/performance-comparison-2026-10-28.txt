Fresh Windows and physical Android performance measurements, 2026-10-28
======================================================================

Results
-------

matching workloads; lower allocations alone have not established lower latency.
Historical timings are comparisons, not a controlled attribution to one change.

Method and comparability
------------------------
Android: two batches, each with 10 measured edits per action for 3- and 20-entry
Death Guard armies, plus five fresh-process launches. One unrecorded warm-up
per editing action. Both editing batches are pooled, not selected by best run.
Command-to-usable includes shared command, preparation and MAUI presentation.
Warm filesystem/derived caches; neither device reboot nor OS cache flushing.
The first startup batch restored a 2-entry enhancement-check fixture and is
excluded from the 20-entry startup comparison. The second batch restored a
20-entry performance fixture; the prior record restored a different 20-entry
attachment-check fixture. Startup comparison therefore remains approximate.

Windows shared command: three processes, five samples each per 3/20-entry
equipment workload (15 pooled samples per size). Same historical library JSON
fixture and harness; timings exclude UI preparation/rendering. Compare medians
with editing-2026-10-28.json's uncontended "after" record. The concurrent-build
record in that file is deliberately not used as baseline.

Windows WPF diagnostic: actual current MainWindow, resources and shared session,
its own marked synthetic database, ten saved armies, eight actions, 3/20-entry
rosters, ten samples/action/size (160 total), one unrecorded warm-up/action.
Two rendering callbacks and dispatcher idle after each presentation. The host
launches hidden; Windows may throttle its rendering callbacks. Consequently
these timings are NOT a valid visible-window latency comparison or proof of a
UI regression. Historical October 13 values are retained only as context,
because window visibility, catalogue and instrumentation differ. The host also
loads loose XAML resources outside its app-entry timer and omits the production
loading splash. Its process-start metric includes resource loading. Five warm
launches reuse ten saved synthetic armies. Do not describe them as installed
production startup timings.

Storage: each platform writes and reads the bundled catalogue through both
legacy full snapshots and shared objects over three revisions. Full field
round trips, provenance changes and a single price change are checked. One
sample per revision/mode: useful allocation/storage evidence, not a robust
latency distribution. No internet download time is included.

Reproduction
------------
Shared Windows command workload:
dotnet tools/GrimList.Performance/bin/Release/net10.0/GrimList.Performance.dll tests/fixtures/libraries/GrimList-Library.json <new-disposable-directory>
Windows storage workload (matching prior Debug measurement):
dotnet tools/GrimList.Performance/bin/Debug/net10.0/GrimList.Performance.dll --catalogue-storage <new-disposable-directory>
Android:
python scripts/Measure-AndroidPerformance.py --apk artifacts/builds/android-performance/0.2.28/GrimList-Performance-0.2.28.apk --serial <connected-device> --output <report-directory> --iterations 10 --starts 5 --skip-install
Only use --skip-install after verifying the installed isolated APK hash.
python scripts/Check-AndroidPerformanceApp.py --serial <connected-device> --output <report-directory> --checks catalogueStorageChecks
Hidden Windows diagnostic (not visible-window frame latency):
dotnet build tools/GrimList.WindowsPerformance/GrimList.WindowsPerformance.csproj -c Release -p:OutputPath=bin/Performance/ -p:NuGetAudit=false -m:1 -nr:false -p:UseSharedCompilation=false
python scripts/Measure-WindowsPerformance.py --database <new-disposable-directory> --output <new-report-directory>
Use a new report directory; failed-run error markers must not be mistaken for
the next run. Do not point this host at a live library. It refuses a preexisting
database directory without its own disposable-fixture marker.

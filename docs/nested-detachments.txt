Nested BSData detachment fix — 2026-10-26 (unreleased)

Problem

The user's downloaded BSData 11e revision
79c2aff2dcf7663b53e6b1c52fb36a564d5ab054 contains thirteen Custodes choices.
Six reside under a selectionEntryGroup named "Shield Host Detachments (Max 1)".
The importer read only direct upgrade children of Detachment/Detachments
containers. It imported seven choices, missed six rule/enhancement scopes,
and correctly refused to authorize retirement from that incomplete result.
Consequently five obsolete definitions survived the user's update.

The observed library had twelve choices (seven current plus five obsolete).
The source archive's thirteen choices agreed with the edition-specific
Wahapedia list inspected during diagnosis. That is an observation of the
downloaded revision, not a claim that a fresh upstream download was performed.

Implementation

BsDataDetachmentTree walks nested selection groups and resolves group links.
It stops at detachment upgrade leaves, so embedded equipment/upgrades cannot
become extra detachments. ReadReferences and source-authority validation use
the same traversal. No faction, unit, detachment or subgroup name is hard-coded
into the new traversal or limit evaluation.

Inherited visibility stays with the detachment and its nested reference cards,
including enhancement eligibility. Missing links, cycles, unsupported group
constraints and conditionally modified limits prevent authoritative retirement.
Unsupported group constraints also leave their choices unavailable rather
than silently permitting an invalid combination.

DetachmentGroupLimit stores source group identity, name and numeric maximum.
Optional GroupLimits metadata survives JSON, SQLite and faction loading.
Shared DetachmentRules enforces limits in picker eligibility, validation and
exports; both frontends already call those shared paths. The outer selector's
own count constraints are not mistaken for a maximum number of detachments.
Existing DP budget logic remains responsible for battle-size limits.

For this pinned revision, all thirteen choices and six formerly missing rule
and enhancement scopes import. Selecting Aquilan Shield plus Solar Watch is
rejected; Aquilan Shield plus Auric Champions remains permitted within budget.
A complete authoritative apply retires Shield Host, Talons of the Emperor,
Solar Spearhead, Silent Hunters and Tharanatoi Hammerblow. Saved obsolete
selections remain visible with review warnings; no replacement is guessed.

Applying the fix

Restart through Start-GrimList.cmd to build/run the updated source, then use
Update BSData and apply the combined update preview. An already running app
and the shipped 0.2.26 packages do not acquire this code automatically.
This task does not directly edit the live database or rebuild release packages.

Regression coverage

unmodified pinned repository archive, with SHA-256 validation. The real source
test runs the production ImportAll path over Custodes' dependency closure.
Coverage includes thirteen choices, scoped rules and enhancements, numeric
limits, inherited visibility, malformed/conditional input, serialization,
retirement preview/apply, saved-army preservation, startup recovery and export.
The fixture includes no user database or saved armies.

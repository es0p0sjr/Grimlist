# Conditional rules and effective attachment state

## Generic engine changes

The effective projection evaluates a complete proposed army in dependency passes.
It establishes selection and enhancement effects before evaluating legal attachment
groups, then resolves attached benefits against complete snapshots until stable.
Every pass starts from the immutable imported profiles. Modifier increments do not
accumulate between passes. Unknown conditions do not activate grants; conflicting
cycles disable dependent effects and produce a validation diagnostic.

Conditions can query local equipment/choices, enhancement selection and eligibility,
detachment combinations, catalogue context, effective keywords, roster members,
model counts and legal associated/attached members. Boolean AND/OR/NOT predicates
retain their source structure. Only legal relationships provide attached benefits.
The existing source-defined attachment capacity and combination restrictions still
apply, and category counts use effective keywords rather than removed base tags.

Immutable army/dataset snapshots share evaluated results through weak caches.
Edits, proposed states, imports and undo/redo use new snapshots. There is no stored
derived FNP, keyword, characteristic or attachment permission on the base unit.

Structured attachment predicates distinguish the prospective Bodyguard from the
granting model (`queryFromSelf`). They can expand or restrict the base recipient
set when a selection changes. Invalid saved relationships remain visible for
repair and are reported by validation, but grant no dependent effects.

Windows and Android use the same projected abilities, defensive stats, weapon
profiles and attachment candidates. Library previews also use the current army
context. Inactive equipment abilities are no longer appended back into the
datasheet from the base profile. PDF exports already consume this shared projection.
The datasheet continues to show current values only.
Legacy diagnostic wording now distinguishes unresolved conditions from the effects
that the projection has evaluated. Native Android testing also exposed retained
Redo controls remaining disabled after an incremental attachment refresh. Attachment
edits now rebuild the current view from the complete effective snapshot, as rule
and enhancement edits already do, preserving the session's undo/redo history.

## Source and importer changes

Version 2 datasheet semantics retain scoped abilities, conditional ability-name/text
modifiers, structured attachment predicates and selection-node profile/keyword/rule
effects. Nested visibility/selection conditions are propagated into their effects.
Root catalogue picker visibility is separate from the rules of a unit already in
the roster. Pure constant conditions are simplified during import.

There are no faction, unit, enhancement or source-ID special cases in this change.
Named examples occur in tests. Murdermind's expanded targets are encoded in the
source Technomancer association predicate; no permission was inferred from its
short enhancement description or added through a manual mapping.

The shared `effective-datasheets.json.gz` resource is regenerated by the production
importer for the two validated source archives (cc1830fb and da724877 revisions).
Existing libraries receive semantic metadata in memory only when archive identity,
base characteristics/weapons and ability text match. Enhancement metadata also
requires an exact source and text match. Repeated recovery is idempotent, and saved
armies and bootstrap release content are unchanged.

## Regression cases

- Lokhust Destroyers have no granted FNP without a legal qualifying attachment.
  Murdermind grants the source keyword/movement effect and enables the structured
  Technomancer attachment. Attachment grants FNP; detachment, enhancement or
  prerequisite removal removes the benefit and reports an illegal remaining link.
- Switching Necron detachments removes the old detachment abilities and exposes
  the selected detachment's rule.
- Thousand Sons: Bray Lord permits an Infernal Master to attach to Tzaangors;
  the attached weapon ability appears and disappears with its prerequisites.
- Adeptus Mechanicus: the Tech-Priest Dominus FNP grant on Kataphron Breachers
  requires a legal attachment.
- Aeldari: the Autarch's Fights First visibility follows its current Bodyguard.
  This exercises the same conditional rule mechanism outside Necrons. The source
  audit found the specific shared group containing all detachment abilities in
  Necrons, rather than an equivalent all-detachment group in another faction.
- Synthetic tests cover conditional characteristics, weapons, keywords,
  invulnerable saves and abilities; removed granting rules; dependency/entry order;
  unknown conditions; cycles; immutable base data; proposed states; persistence;
  and undo/redo. Existing Daemon Prince/allegiance/enhancement regressions remain
  part of the full suite.

## Remaining source limitations

No missing source information or manual compatibility mapping was needed for the
named regression cases. The source's explicit attachment target predicates are
authoritative; a granted keyword alone does not imply permission to attach to
every unit with that keyword.

Arbitrary source query languages, unsupported repeat/local-query constructs and
unrecognized prose are not treated as unconditional permissions or stat changes.
Battlefield position, temporary phase effects and other undetermined conditions
remain contextual. Original source text remains available in the base data.

An old flattened library from an unrecognized archive cannot reconstruct lost
conditions from its display text alone. It needs a new import of its original
source; the bundled recovery deliberately does not guess across source versions
or overwrite modified base abilities. The validated bundled/current libraries
are covered by the generated metadata.

The verification builds above are retained as implementation evidence. These
changes are now packaged in [release 0.2.3](distribution/release-0.2.3.md), with its
Windows installer and Android APK together in `GrimList-Share-0.2.3/`.

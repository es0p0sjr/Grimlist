# Detachment applicability, linked costs and bug reports

## Source trace and fixes

The validated BSData archive stores Armoured Speartip's **3 Detachment Points** on an entry link in the Space Marines catalogue. Its shared definition in the Astartes Heresy Legends library has no price. `BsDataImporter.Resolve` previously retained link-local selection rules but discarded link-local costs. It now overlays costs by cost type, preserving other costs from the shared definition. `ReadReferences` resolves cost-type definitions and normalizes integral numeric values (including `3.0`) to `3 DP`.

The resulting `DetachmentDefinition.Cost` passes through import/merge/persistence and the shared `DetachmentRules` projection to the WPF and MAUI selectors. No detachment-name, unit-ID or chapter-name exceptions were introduced.

Angelic Inheritors is stored on the shared source page, with a `hidden = true` modifier when the primary catalogue is not its permitted catalogue. Imported detachment `Applicability` now retains these conditions as a boolean expression. `Dataset.FactionContexts` records primary catalogue identity and source keywords independently of shared-page ownership. Selectors evaluate the complete army context; conditions can combine catalogue, faction keyword and selected-detachment predicates. Unsupported conditions do not grant permission. Existing illegal selections remain saved and receive an explicit validation reason.

Both platforms load `detachment-metadata.json.gz` from the shared Application assembly to repair missing metadata in older libraries. The resource is generated by the production resolver, matched to the exact source archive hash, and only fills missing costs/applicability/context. It does not change armies, overwrite explicit prices, or read a repository/source archive at runtime. It covers the validated `cc1830…` and `da7248…` archives.

Rebuild a recovery pack (the command replaces that archive's entry and retains other entries):

```powershell
dotnet tests/GrimList.Tests/bin/Debug/net10.0/GrimList.Tests.dll --build-detachment-metadata <repository.zip> src/GrimList.Application/Resources/detachment-metadata.json.gz
```

Reference acquisition, network behaviour and reference prose parsing are unchanged. The BSData resolver/reference extractor changed only to retain the required cost and selection semantics. The small Tyranid nomination fixture now includes the force definition cited by its visibility condition; previously the isolated fixture omitted that dependency.

## Report a Bug

Windows exposes the action on Home and the roster menu. Android exposes it in the menu. Required fields are a short title and description/steps. Expected and actual results and up to five selected images are optional.

The shared reporting service creates a ZIP containing `bug-report.json` and, when selected, `images/image-1.png`, etc. JSON format version 1 includes the draft, UTC creation time, diagnostics and an image inventory with sizes and SHA-256 hashes. Review displays the exact JSON and selected image previews. Editing text or attachments invalidates the reviewed snapshot and disables export/share until another review. No backend, automatic submission or telemetry is involved.

Diagnostics use an explicit allowlist: app/platform/OS version; source release/version, archive hash and data schema; current faction/detachments; validation findings; canonical unit names, model counts, enhancement/choice/equipment selections and Warlord flags. Reports from Home contain no roster. Army names, custom entry names, notes, roster IDs, unrelated armies, source URLs and local files are excluded. Paths, addresses, usernames and recognizable credential strings are redacted. The bounded, in-memory error ring retains exception types, error codes and technical method names; it does not retain exception messages, arguments, stack file paths or read disk logs.

Only files explicitly selected in the image picker are read. Reads are bounded to 10 MB per image, with 25 MB total and five images maximum. Platform image decoders validate the selected images; images above 40 megapixels are rejected. PNG re-encoding and chunk filtering remove filenames, EXIF/location and other ancillary metadata. Invalid images produce an understandable error and reports remain usable without images. Users review their own entered text and image content before sharing.

`IBugReportService` owns preparation/export, `IBugReportDestination` owns delivery, and `IFileSharing` isolates platform sharing. A future destination can use the same reviewed package/domain model. Windows uses its per-window WinRT share sheet and a Save ZIP dialog; Android uses MAUI sharing and the existing Android document-save adapter. Shared ZIPs are stored in the platform cache. Cancelling a picker/share does not discard the form.

Windows targets the Windows SDK to support unpackaged WPF sharing. The adapter follows Microsoft's [per-window DataTransferManager interop](https://learn.microsoft.com/en-us/windows/apps/develop/ui/display-ui-objects#for-classes-that-implement-idatatransfermanagerinterop). The offline Windows publishing script now lets .NET resolve its compatible runtime version without accidentally overriding the separate WinRT SDK runtime-pack version.
